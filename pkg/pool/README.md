# pool

Типизированный контейнер поверх `sync.Pool` для объектов с методом `Reset()`.
При `Put` объект сначала сбрасывается и только затем становится доступен
следующему пользователю пула.

```go
buffers := pool.New(func() *bytes.Buffer { return new(bytes.Buffer) })
buffer := buffers.Get()
defer buffers.Put(buffer)

buffer.WriteString("metrics")
```

API:

```go
type Resetter interface { Reset() }
func New[T Resetter](factory func() T) *Pool[T]
func (p *Pool[T]) Get() T
func (p *Pool[T]) Put(value T)
```

`Get` получает объект из пула, а при отсутствии свободного объекта вызывает
фабрику. Фабрика должна быть ненулевой, допускать параллельные вызовы и создавать
отдельные готовые объекты, отличные от `nil`. В `Put` передают объект, отличный
от `nil`, включая типизированный `nil`.

Пул поддерживает параллельные `Get` и `Put`. Между ними объект принадлежит
одному вызывающему; после `Put` владение передаётся пулу. Сам `Pool` после начала
использования нельзя копировать.

`sync.Pool` может удалить сохранённые элементы в любой момент, поэтому очередной
`Get` может создать новый экземпляр. Это кеш для повторного использования,
а не хранилище объектов с гарантированным временем жизни.

В проекте контейнер совместим со сгенерированным `(*models.Metrics).Reset()`.
Это проверяется вместе с параллельными вызовами, поведением после GC и сбросом
состояния до завершения `Put`:

```sh
go test -race ./pkg/pool
```
