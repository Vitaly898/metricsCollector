# cmd/server

Сервер принимает и хранит метрики. Запуск из корня репозитория:

```sh
go run ./cmd/server
```

## Аудит запросов

Приёмники аудита включаются независимо:

| Флаг | Переменная окружения | Назначение |
| --- | --- | --- |
| `--audit-file` | `AUDIT_FILE` | Путь к файлу JSON Lines, события добавляются в конец |
| `--audit-url` | `AUDIT_URL` | Полный HTTP/HTTPS URL для отправки событий методом POST |

Переменные окружения имеют приоритет над флагами. Пустое значение отключает соответствующий приёмник; по умолчанию оба отключены.

```sh
go run ./cmd/server --audit-file=/tmp/audit.jsonl --audit-url=http://localhost:9000/audit
```

Одно событие создаётся после успешного сохранения метрик из запроса на `/update/{type}/{name}/{value}`, `/update`, `/update/` или `/updates/`:

```json
{"ts":12345678,"metrics":["Alloc","Frees"],"ip_address":"192.168.0.42"}
```

`ts` — Unix-время события в секундах. Для пакета сохраняются имена метрик в порядке запроса, включая повторяющиеся. IP берётся из адреса соединения без порта; заголовки прокси не используются.

Наблюдатели регистрируются при запуске и уведомляются синхронно. HTTP-запрос имеет таймаут две секунды, успешными считаются ответы `2xx`; перенаправления не выполняются. Ошибки доставки записываются в лог, остальные наблюдатели всё равно получают событие, а результат сохранения метрик остаётся успешным. Повторных отправок и фоновой очереди нет.

Некорректный URL или невозможность открыть файл приводят к ошибке запуска. Файл закрывается после остановки HTTP-сервера.
