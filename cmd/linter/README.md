# linter

Отдельный запуск собственного анализатора через `singlechecker`.
Полный набор стандартных и публичных проверок находится в `cmd/staticlint`.

Запуск из корня проекта:

```sh
go run ./cmd/linter ./...
```

Анализатор проверяет исходники и тесты выбранных пакетов:

- запрещает вызовы встроенной функции `panic` во всех функциях, включая `main`;
- запрещает прямые вызовы `os.Exit` в функции `main` пакета `main`;
- запрещает прямые вызовы `log.Fatal`, `log.Fatalf` и `log.Fatalln`
  вне функции `main` пакета `main`.

Анонимная функция внутри `main`, функция `main` другого пакета и метод с таким
именем считаются обычными функциями: в них разрешён `os.Exit`, но запрещены
`log.Fatal*`. Импорты с псевдонимами и точкой учитываются; одноимённые пользовательские
функции, затенённые имена, методы `testing.T` и `log.Logger` не вызывают диагностику.
Косвенные вызовы через переменные функционального типа не отслеживаются.
Служебные `main` тестовых бинарников, создаваемые `go test`, исключены;
сгенерированные исходники самого проекта проверяются.

Общая реализация и тесты находятся в `internal/analyzer/exitcheck`.
Тесты с ожидаемыми диагностиками в `testdata` запускаются через
`golang.org/x/tools/go/analysis/analysistest`:

```sh
go test ./internal/analyzer/exitcheck
```

Go исключает каталог `testdata` из шаблона `./...`; примеры нарушений проверяются
только при запуске тестов анализатора.
